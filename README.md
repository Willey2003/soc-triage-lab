# Private AI-Powered SOC Triage Lab

Can a small local LLM take tier-1 alert triage off a SOC team without missing attacks or being talked out of
an escalation by the attacker? This lab measures it.

The same labelled alerts go through three designs:

- **rules**: a classic SIEM threshold
- **llm**: a model decides everything
- **hybrid**: rules at both ends, the model only in the grey zone, with an injection guard and fail-safe defaults

Everything runs on one VM, with no GPU and no data leaving the box.

**Result (qwen2.5:1.5b, 120 alerts):** the hybrid design cut the analyst queue from 100 to 83 alerts and the false positives from 40 to 23. It missed 0 attacks, and 0 prompt injections succeeded. Letting the model decide everything was worse than the plain rules: it missed 7 attacks, and 1 of 10 injections succeeded. Results are in [RESULTS.md](RESULTS.md), and the design is in
[ARCHITECTURE.md](ARCHITECTURE.md).

```
feeder ─▶ API ─▶ enrich ─▶ rule score ─▶ hybrid gate ─▶ (grey zone) ─▶ Ollama qwen2.5:1.5b
                                  │                           │
                              SQLite cases ◀───────────────────┘   Prometheus ◀─ /metrics   Grafana dashboard
```

## Run it (rootless podman)

Requirements: podman 4.4+ (tested on 5.6, RHEL 9, rootless, SELinux enforcing), about 4 CPUs, 6 GB RAM and 3 GB disk,
plus egress to docker.io and registry.ollama.ai.

```bash
git clone https://github.com/Willey2003/soc-triage-lab && cd soc-triage-lab
scripts/lab.sh up        # build image, podman kube play, pull qwen2.5:1.5b, wait until ready
scripts/lab.sh status
scripts/lab.sh eval 120  # rules vs llm vs hybrid on 120 labelled alerts -> eval/results/latest.md
scripts/lab.sh test      # unit tests inside the image
scripts/lab.sh tunnel    # prints the ssh -L command for your workstation
scripts/lab.sh down      # stop (volumes kept); `purge` removes volumes and the image
```

Every port is bound to 127.0.0.1 on the VM:

| What | URL (through the tunnel) |
|---|---|
| Analyst console + API | http://127.0.0.1:18090 (`/cases`, `/ingest`, `/triage`, `/metrics`, `/docs`) |
| Grafana (anonymous viewer) | http://127.0.0.1:13000 (admin password in `~/.soc-triage/grafana-admin`) |
| Prometheus | http://127.0.0.1:19090 |

Try one alert yourself:

```bash
curl -s localhost:18090/triage?mode=hybrid -H 'content-type: application/json' -d '{
  "id":"demo-1","rule":{"id":"IDN-004","name":"Impossible travel"},
  "event":{"category":"authentication","action":"sso_login","outcome":"success"},
  "source":{"ip":"185.199.110.10","geo":{"country":"DE"}},"user":{"name":"m.chen"},
  "travel":{"previous_country":"US","minutes_between":40,"new_device":false,"mfa":"push_approved"}}' | jq
```

## Run it on Kubernetes

```bash
helm install soc deploy/helm/soc-triage -n soc-triage --create-namespace \
  --set image.repository=<your registry>/soc-triage --set image.tag=0.1
kubectl -n soc-triage port-forward svc/soc-api 8090
```

The chart creates Ollama (with a PVC and a post-install Job that pulls the model), the API (with a PVC and probes,
running as non-root), the feeder, a NetworkPolicy so only the API can reach Ollama, and an optional ServiceMonitor.

## Repository

| Path | What |
|---|---|
| `app/generator.py` | synthetic ECS-style alerts: malicious variants, benign look-alikes, prompt-injection cases |
| `app/enrich.py` | threat intel, CMDB, users, MITRE ATT&CK candidates (local JSON in `data/`) |
| `app/rules.py` | deterministic risk score (what a SIEM rule knows) |
| `app/guard.py` | prompt-injection detection and sanitizing |
| `app/llm.py` | Ollama client, prompts, JSON-schema output |
| `app/triage.py` | the three modes |
| `app/api.py`, `app/ui.html`, `app/store.py` | FastAPI service, analyst console, SQLite cases, Prometheus metrics |
| `eval/run_eval.py` | offline evaluation harness |
| `deploy/podman/` | pod YAML (generated by `scripts/render_pod.py`), Prometheus config, Grafana dashboard |
| `deploy/helm/soc-triage/` | Helm chart |
| `tests/` | pytest with a fake model: rule floor, injection guard, fail-safe, truth isolation, API |

## Safety notes

- All indicators, hosts and users are synthetic. RFC 5737 documentation IPs are used; the hashes and domains are invented.
- This is a lab. Treat the model's output as a suggestion that a human reviews, and keep high-risk alerts on deterministic rules, as the hybrid mode does.

## CI

`ci/github-actions-ci.yml` runs ruff, pytest, helm lint, a pod-YAML drift check and the image build plus tests.
To enable it, copy it to `.github/workflows/ci.yml`. Pushing workflow files needs a token with the *Workflows* permission.
